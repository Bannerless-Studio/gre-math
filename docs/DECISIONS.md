# Decisions (owner-delegated, 2026-10-12)

Resolves SPEC.md section 9 and reconciles SPEC levels with CURRICULUM tiers.

1. One HTML per pack (vocab-engine model). KaTeX core-font subset inlined per page.
2. Correctness: executable checks + blind solve in the pipeline; owner spot-checks 10% of the first 200 items.
3. Licence: engine MIT, items CC BY-SA 4.0 (same as vocab-engine packs).
4. Full problems: timed 5-option MCQ first, then solution reveal + method self-grade. Micro: free-response where checkable.
5. Expression input: ASCII with live preview; no keypad in v1.
6. Levels = CURRICULUM tiers T1–T10, not SPEC's L0–L6. SPEC level ids are superseded; `pack.levels` lists T1..T10. Technique ids come from CURRICULUM.md JSON.
7. Seed pack for M1 = gre-math T1 (first ~10 techniques), not a throwaway `packs/seed`.
8. Model policy: Haiku 5.5 first-pass builds and recall/micro item generation (answers code-verified); Sonnet 5.5 for full items, reviews, Haiku failures; Opus only after Sonnet fails.
9. Placement (reconciles SPEC §6 with CURRICULUM §4): mechanism = SPEC §6 (vocab-proven adaptive walk: ascending, cumulative accuracy ≥ 0.7 prefix rule, isolated-zero tolerance, early stop on 3 zero buckets, placed techniques `{s:1, prov:1}`, retake only forward, no day-based intervals). Buckets = tiers T1..T9, one bucket each, 5 probe items per tier drawn from the CURRICULUM §4 probe technique lists; probes are tier b items flagged `probe: true` (each content batch must author one probe per listed technique). MCQ probes get an explicit "I don't know" option (scores 0). Cross-tier prereq exception (T6 before T3–T5) is a recommendation only; the gate stays linear.

M6 decisions (resolved on the owner's behalf, to confirm):
- Placement stops: the CURRICULUM 4.2 low run (two buckets under 0.7) is added to SPEC 6's zero run, because SPEC 6 as written closes on the first bucket under 0.7 and then the isolated-zero rule could never apply.
- Placement knowns: provisional techniques count as known for the gate and as prerequisites. Without this a placed learner sees the gate hold on a level they were placed through (SPEC 6 wordKnownP).
- Probes: "I don't know" is offered on every probe, typed ones too, scoring 0 with no attempt. Typed probes would otherwise have no way to decline.
- Review at streak 2: when a tier a recall pool has no typed item, the typed card comes from tier b. Without this, recall MCQ fills the per-technique cap and streaks never move past 2.
- Summary: missed solutions sit behind a fold. The solution already showed at the reveal.
- Retake UI: not offered (decision 9). The core applies forward-only retakes, tested.
10. Numeric tolerance is relative, never an absolute floor (2026-10-13, physics pack prep). Expression sampling and numeric float checks used `1e-9 * max(1, |v|)`, which accepted any value within 1e-9 of a target near 1e-19; the decimal branch had a 1e-12 absolute slack. Both are now relative to the value. `rel` (0 to 0.1) applies to decimal and float targets. Exact rational targets under `exact` still compare exactly. Exception (review fix): exact-zero targets, which have no relative scale, keep a `1e-12` absolute slack (numeric expression input; expression items when one side is identically 0), because float cancellation never lands on 0.
11. Scientific literals (`3e8`, `1.6e-19`) are accepted as typed numeric answers, and still rejected in expressions because `2e-1` is ambiguous there (2026-10-13).
12. Figures are inline SVG on items and teach cards, gated at build time by `tools/figure.js`; the page inserts them as HTML. Allowlist and rules in `docs/PACK_SCHEMA.md` "Figures" (2026-10-13).
13. Code answers: Python run in the browser (2026-10-13, data-structures pack prep; the brief called this entry 11, but 11 and 12 were taken). New `answer.kind` `code`: the learner edits a function in a textarea, Run tests shows per-test results, Check grades all tests and counts as a typed (production) answer. Python runs in Pyodide 0.26.4 loaded lazily from jsdelivr in a Web Worker (`engine/pyworker.js`, inlined as text, started from a Blob URL), with a 10 s wall-clock limit enforced by terminating the worker. The runner only produces raw results through `engine/pyharness.py`; all grading is `checkCode` in `engine/answer.js` (tolerant equality, pure JS, node-testable). The same harness file is used by `tools/run_code_items.py`, which runs every item's reference code (first fenced block of `solution`) against its tests in local CPython and fails on a mismatch or on a starter that already passes. Reasons: the DS pack needs real code answers; a numeric or MCQ proxy would test recognition, not writing. Costs: a one-time ~10 MB download (numpy and pandas add more), cached by `sw.js` in a separate `pe:pyodide:v0.26.4` cache that survives page builds. Risks accepted: the first code card needs network once; a Python outage shows a hint and counts nothing; the worker is not a hard sandbox (network functions are disabled during a run on a best-effort basis). Code is not allowed on tier c. Packages limited to numpy and pandas. Fenced code blocks (three backticks) are now part of Markdown-lite in `engine/text.js` (literal, no math).

14. Code answers review (2026-10-13): grading compares in JS only; with no explicit `tol` an integer `expect` needs an exact integer (relative 1e-9 alone accepted 1e12 + 500); ints beyond 2^53 - 1 travel as `{"__i": digits}` and the validator rejects them as bare numbers; the harness binds its JSON encoder and builtins at load and restores builtins/json after each run (a `json.dumps` patch forged results and persisted into later runs of the same worker); the Pyodide cache moved from shared `pe:pyodide:v0.26.4` to per-scope `PREFIX + "pyodide-v0.26.4"` so the kill switch and site isolation work unchanged (cost: one copy per site on a shared origin); Pyodide fetched in cors mode, opaque responses never stored; offline first visit gets a Skip (no attempt, no credit) because the engine has no other way off a card; `run_code_items.py` fails on a missing package unless `--allow-skip`, and its timeout is a BaseException so the harness cannot swallow it (before, a looping reference solution hung the tool).
15. Opus engine review fixes (2026-10-13; findings D1-D6, L1-L6, A1-A7, S1, V1-V3, T1-T2, Q1). Owner decisions: L4, the streak caps at `mastered + 1`; L6, a technique loses at most one streak step per session. Other behaviour changes: the level exam moves no streaks and consumes no ordinal (L1); a placed technique stays known when it masters (L2); credit needs `l < session ordinal`; full grade 0 resets critical secondaries (L3); grade 2 clears `wk` (L5); a stale tab goes read-only instead of overwriting another tab's progress (D1); `PE_BUILD` is defined before app.js runs so the resume build check works (D2); Export in read-only mode writes the stored text (D4); a backup slot holding progress is never overwritten by an empty record (D5); unknown fields survive in `full` and `day` (D6); the checker no longer accepts typed-undefined points, tiny-target zeros, zero-width domains or 16-digit literals (A1-A3, A5); the validator checks every numeric and expression key against itself and refuses a technique with no tier b item below the last level (V1, V2); `X_1` and `X1` are one variable in typed expressions. Re-review (2026-10-13): the exam does not reset critical secondaries either; a streak saved above the cap drops under it at its first miss; a stale tab refuses import and reset before writing a backup; deploy_pack also reads the pack key of pages built before the marker. Exam offer (2026-10-13): offered when the previous level's known share is in [0.65, 0.70) or is the last count below the gate (`known/n < 0.7 <= (known+1)/n`), since n = 5, 14, 17 have no count in the window (`examOffered` in core.js). Follow-ups (2026-10-13): J1, `_pre_import_backup` and `_reset_backup` are 2-slot rings (slot 0 is the old key, so an existing record is slot 0; slot 1 is `<key>_1`; a slot with progress is never displaced by an empty record); J2, a level exam miss on a placed technique clears `prov` and moves no streak; J5, read-only Export writes the record currently in localStorage (`store.raw()`), then the text read at open (D4), then this tab's progress.

17. Ladder kind (2026-10-13, algo-discovery pack prep). New `answer.kind` `ladder` for tier b items: 3 to 7 staged interventions (`choose`, `counterexample`, `typed`) that walk a learner from a competitive-programming statement to the mental move, grading the process (hints, wrong attempts, Show me) instead of one final answer. Why: the pack teaches discovery (what to try, what to doubt), which a single numeric or MCQ answer cannot test and a free-form AI coach cannot be shipped in a static page; staged, deterministic prompts with authored wrong-option feedback are the coach stand-in. Counterexample stages run the author's `breaks(inp)` on the learner's input in the existing Pyodide worker and harness (`run` with one test), so no new runtime. Grading rule: stage grade 2 = first try, no hint; 1 = a hint, or exactly one wrong attempt (hint plus one wrong is also 1); 0 = Show me or two or more wrong attempts. Item grade = min over stages. Grade 2 applies as a right micro answer (credit once per session, streak cap, production gate, `fp`). Grade 1 is a hold, not a miss: nothing moves except `items[id].l` and `st`; it is not scored, not listed under Missed, not in the day log, and writes no `t`. Grade 0 applies as a miss (reset, Recent misses, Missed list) without a requeue because a ladder is long. A ladder is production iff it has a `counterexample` or `typed` stage. Stage grades are kept in `items[id].st`. Finished-card verdict: Clean / Got there with help / Took several tries (grade 0 from wrong attempts) / Needed the answer shown (Show me). Ladders are excluded from placement probes and from the level exam's micro set (both assume one answer per card), so a pack whose tier b items are all ladders has no placement or exam path; the Test tab hides the offers that cannot run (`examPlayable`, `placementPlan`). The ladder card drops the pinned-stimulus top offset (`.drill-body.lad`) because stages grow the card downward. Grade 1 holds by changing nothing rather than reusing `applyFullGrade`, whose `fp`/`wk` flags belong to tier c full problems.
